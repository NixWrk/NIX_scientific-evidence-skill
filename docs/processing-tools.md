# Кандидаты для обработки существующего научного корпуса

Этот документ содержит только компоненты, которые можно тестировать на уже имеющихся материалах Zotero для трёх результатов: вопрос/ответ, литературный обзор и итоговая статья.

## 1. Фиксированный слой доступа

### Zotero MCP

Zotero MCP уже установлен и принимается как штатный интерфейс к корпусу. В репозитории не требуется выбирать другой Zotero MCP.

Проверяемые функции этого слоя:

- получение элементов заданной коллекции;
- чтение метаданных;
- получение HTML полного текста;
- получение заметок и аннотаций;
- связь HTML, PDF и записи Zotero;
- сохранение стабильного `zotero_item_key` в результатах эксперимента.

Основной риск — потеря структуры или происхождения текста при передаче следующему компоненту. Поэтому сырой ответ Zotero MCP и его нормализованное представление сохраняются раздельно.

## 2. Базовые конвейеры

### 2.1. Прямой baseline

```text
Zotero MCP
→ HTML выбранных статей
→ LLM/агент
→ ответ, обзор или раздел статьи
→ аудит утверждений по исходному HTML
```

Этот вариант устанавливает минимальный уровень качества и стоимости. Он подходит для небольшого корпуса, но может терять доказательства при длинном контексте.

### 2.2. Evidence-first

```text
Zotero MCP
→ нормализация HTML/PDF
→ извлечение фактов и фрагментов
→ evidence_table
→ отдельный этап синтеза
→ аудит утверждений и чисел
```

Это основной эталонный workflow репозитория.

Первая переносимая реализация —
[`scientific-evidence-workflow`](../skills/scientific-evidence-workflow/SKILL.md).
В `EXP-0021` она прошла структурные тесты и неслепой Q&A smoke на текущем
Codex-агенте. Контракт не требует MCP, function calling или внешнего model API;
фактический прогон на отдельной локальной LLM остаётся следующим portability
test. До слепого сравнения с direct Q&A этот результат не считается готовым
baseline.

В `EXP-0022` workflow также сравнен с direct narrative review на восьми
публикациях по УЗИ межрёберных мышц. Обе ветки дали корректный научный вывод и
выявили ретракцию; skill-ветка добавила 31 проверяемый evidence locator и 12
claim records без доказанного прироста точности текста. Результат подтверждает
аудируемость, но остаётся неслепым сравнением тем же агентом.

### 2.3. Корпусный RAG

```text
Zotero MCP
→ локальный индекс корпуса
→ извлечение релевантных фрагментов
→ evidence_table
→ генерация
→ аудит
```

Он предназначен для коллекций, которые нельзя надёжно поместить в один контекст модели.

## 3. Инструменты-кандидаты

### 3.1. GROBID

GROBID нужен только как резервный структурный разборщик PDF, когда Zotero не предоставляет пригодный HTML или когда требуется проверить страницы и библиографическую структуру PDF.

Тестировать необходимо:

- заголовки и секции;
- библиографические ссылки;
- привязку текста к страницам;
- числа, формулы и подписи;
- устойчивость на сложной вёрстке.

Если HTML из Zotero качественнее, дополнительный разбор PDF не должен быть обязательным этапом.

### 3.2. Локальный файловый или векторный индекс

Нейтральный baseline для проверки, насколько специализированная система превосходит простой индекс существующего корпуса.

Индекс должен хранить:

- `source_id`;
- `zotero_item_key`;
- секцию документа;
- точный текст фрагмента;
- HTML-локатор или страницу;
- хэш исходного документа.

Конкретные реализации сравниваются на одном наборе фрагментов и одинаковых вопросах.

## 4. Skills и приложения-кандидаты

### 4.1. `literature-triage-matrix`

Переносимый `SKILL.md` для сравнения уже заданных публикаций по вопросу, методу, данным, результатам и ограничениям. В benchmark применяется offline-профиль: только локальные блоки Zotero HTML, без DOI lookup, знаний модели как источника и записи в Zotero.

Основные тесты:

- полнота одинаковых полей для всех публикаций;
- обнаружение противоречий внутри и между источниками;
- разделение сообщаемых результатов и аналитической рекомендации;
- существование каждого указанного `block_id`.

### 4.2. `academic-writing-skills`

Переносимый skill для структуры рукописи, редактирования научного текста и аудита связи «утверждение → доказательство». Он получает только подготовленную `evidence_table`, протокол и утверждённые результаты исследования.

Основные тесты:

- соблюдение заданной структуры;
- корректное использование `source_id`;
- отсутствие вымышленных результатов;
- сохранение чисел и единиц;
- отделение результата исследования от литературной интерпретации.

### 4.3. `sciwrite-lint`

Кандидат для независимого аудита готового текста. В эксперименте учитывается только проверка по предоставленной библиографии и корпусу.

Необходимо измерять отдельно:

- обнаружение несуществующей записи в предоставленной библиографии;
- несоответствие метаданных;
- отсутствие источника у утверждения;
- семантическое несоответствие утверждения цитируемому фрагменту;
- число ложных предупреждений.

## 6. Единый протокол сравнения

Для каждого запуска фиксируются:

```yaml
experiment_id: EXP-0001
task: qa
corpus_id: CORPUS-001
input_representation: zotero_html
tool: direct-agent
tool_version: "..."
skill_version: "..."
model: "..."
parameters: {}
prompt_hash: "..."
corpus_hash: "..."
```

Все кандидаты получают одинаковый корпус, одинаковое задание и одинаковые эталонные материалы. Изменение модели, prompt, skill или способа представления текста создаёт новый эксперимент.

## 7. Критические ошибки

Следующие события считаются отдельными блокирующими метриками:

- источник отсутствует в предоставленном корпусе;
- цитируемый фрагмент не существует;
- локатор ведёт к другому содержанию;
- число или единица изменены;
- вывод сильнее, чем подтверждающий фрагмент;
- результат одного исследования приписан другому;
- отсутствие данных скрыто уверенной формулировкой;
- в Methods или Results добавлена не предоставленная информация;
- инструмент незаявленно использовал внешний материал.

Средняя языковая оценка не может компенсировать критическую ошибку.

## 8. Приоритет экспериментов

### P0

1. Получение HTML и метаданных через установленный Zotero MCP.
2. Нормализация источников и стабильные локаторы.
3. Прямой Q&A baseline по одной и нескольким статьям.
4. Evidence-first Q&A с отдельным аудитом.
5. Проверка точности чисел, таблиц и цитируемых фрагментов.

### P1

1. HTML из Zotero против PDF-разбора GROBID.
2. Литературный обзор по заранее размеченному корпусу.
3. Сравнение direct context и локального RAG при росте объёма корпуса.

### P2

1. Сравнение skills на одинаковой `evidence_table`.
2. Генерация итоговой статьи из замороженных результатов.
3. Независимый аудит рукописи другим инструментом или skill.
4. Регрессионные тесты при обновлении компонентов.

## 9. Рекомендуемый первый эксперимент

```text
Одна коллекция Zotero из 20–50 статей
→ сохранение HTML и метаданных через Zotero MCP
→ 15–30 эталонных вопросов
→ ручная разметка подтверждающих фрагментов
→ direct baseline
→ evidence-first baseline
→ единый слепой аудит результатов
```

Этот эксперимент одновременно проверит преимущество HTML, необходимость отдельного retrieval-слоя и влияние evidence table на достоверность результата.
