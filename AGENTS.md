# Граница репозитория

Этот репозиторий предназначен только для разработки, проверки, документирования
и распространения навыков научной работы.

## Что допускается хранить

- исходные файлы навыков, общие контракты, шаблоны и валидаторы;
- тесты и минимальные фикстуры, необходимые для воспроизводимой проверки навыков;
- документацию архитектуры и правил применения навыков;
- средства сборки, проверки, оценки качества и распространения навыков;
- результаты экспериментов только тогда, когда они необходимы для оценки самого
  навыка, минимальны и не содержат состояние реального пользовательского проекта.

## Что запрещено коммитить

- манифесты и текущее состояние конкретных исследовательских проектов;
- реальные аннотации публикаций, литературные обзоры и иные проектные материалы;
- выгрузки, заметки, ключи заметок и журналы синхронизации Zotero;
- полные тексты источников, извлечённый текст, пользовательские документы и
  результаты исследовательских расчётов;
- временные рабочие файлы и диагностические снимки;
- любые производные материалы, которые нужны конкретному проекту, но не нужны
  для разработки или проверки навыка.

Состояние проекта должно храниться вне этого репозитория: в отдельном рабочем
пространстве проекта и, когда применимо, в Zotero. Если реальный случай нужен
для теста, его следует заменить минимальной синтетической или обезличенной
фикстурой, содержащей только проверяемые свойства.

Перед добавлением файла в индекс Git исполнитель обязан ответить на вопрос:
«Нужен ли этот файл для определения, проверки, документирования или
распространения навыка?» Если нет, файл нельзя коммитить в этот репозиторий.

## Проект и задача пользователя

До выполнения проектно-зависимой работы исполнитель обязан однозначно
установить, к какому проекту относится работа и какую задачу поставил
пользователь. Нельзя угадывать проект, подменять задачу более удобной
формулировкой или автоматически связывать сведения с проектом только по
тематическому сходству.

Если проект, задача или граница между ними неясны, исполнитель обязан сначала
задать пользователю уточняющий вопрос. До получения ответа нельзя создавать или
изменять проектно-зависимые аннотации, обзоры, выводы и состояние проекта.

Каждое новое сведение пользователя, относящееся к проекту, должно быть сохранено
в данных этого проекта с указанием происхождения и состояния принятия. Такое
сведение нельзя оставлять только в истории чата и нельзя автоматически считать
доказательством из научного источника или принятым научным утверждением.

Каноническое место хранения проектных данных пока не определено. До его
определения исполнитель обязан спросить пользователя, куда сохранить новые
сведения, и явно сообщить, если они ещё не перенесены в постоянное хранилище.
Использовать этот репозиторий как временное хранилище состояния проекта
запрещено.
