# EXP-0031 — независимый critic-run диссертации Астапенко

Цель: проверить три диссертационных скилла на полной работе, которая не
участвовала в создании pattern memory, правил или предыдущих gold-наборов.

## Корпус и ослепление

Использована кандидатская диссертация Е. М. Астапенко 2012 года объёмом 130
PDF-страниц. Критику были переданы только PDF и Zotero HTML; существующие
`experiments`, work-patterns и ожидаемые замечания читать было запрещено. После
раскрытия результатов работа перестала быть holdout и стала регрессионным
примером.

Полные PDF/HTML не копируются в репозиторий. Их идентификаторы, хеши и свойства
зафиксированы в `source-manifest.json`.

## Режимы

1. Визуально проверены титульный лист, оглавление, список сокращений и начало
   введения по PDF.
2. На HTML выполнена научная критика введения, методов, результатов, выводов и
   аппарата с PDF/HTML-локаторами.
3. Детерминированные аудиторы сокращений и русского научного стиля запущены на
   извлечённом тексте; исходник не изменялся.
4. Стадии, которым нужны DOCX, протокол, исходные данные, утверждённый result
   ledger, frozen literature boundary или нормативный профиль, помечены
   `blocked/not_assessed`, а не `pass`.

## Итог

Blind-критик нашёл 12 содержательных/аппаратных классов замечаний. Наиболее
существенные: неверное превращение Fisher `p=0,25` в «чувствительность 75%» при
фактических 12/15 = 80%; получение и проверка диагностических порогов на той же
выборке; перенос результатов четырёх отведений на заявленную 10-канальную
систему; невоспроизводимая точность 95%; смешение пациентов и циклов как единиц
анализа; отсутствие независимой проверки и доверительных интервалов.

Прогон также обнаружил дефекты самих скиллов:

- нет адаптера `PDF/HTML -> claim/evidence/result ledger`;
- нет сквозной связи project manifest -> child report -> gate report ->
  фактический файл и SHA-256;
- детектор сокращений дублировал одно замечание для каждого употребления и
  выдавал ложные конфликты из грамматического контекста;
- аудит библиографии принимал malformed record, не сверял `[n]` с номером
  записи и молча игнорировал неизвестную стратегию сортировки;
- поверхностный style-аудит смешивает латинские анатомические термины и
  математические переменные с иноязычной прозой.

В этом же изменении закрыты первые четыре машино-проверяемых дефекта:

- release теперь требует существующие файлы, проверяемые SHA-256, matching
  genre, `validated/final`, child-validator reports и hashed `gate_reports`;
- `ready/in_progress/complete` не опережают зависимости, а optional stages
  должны быть разрешены до release;
- evidence/result не могут выйти за уникальный `input_scope`, `extracted`
  evidence не может поддерживать released claim, а собственные результаты
  квалификационных жанров требуют `approved: true`;
- сокращения дедуплицируются, конфликт значений определяется по утверждённому
  реестру, а базовые библиографические обходы стали fail-closed;
- Word-адаптер до записи DOCX валидирует PSES-журнал, отвергает пустую замену и
  несовпадение `suggested_fix.old` с точным якорем.

После итогового повторного прогона аудитор сокращений выдал 44 уникальных
замечания вместо исходных 177; все оставшиеся требуют ручного экспертного разбора.

Полный release-test на этой диссертации невозможен без исходного DOCX,
протоколов/данных и утверждённых реестров результатов. Это ограничение
зафиксировано как результат теста, а не скрыто как успешная проверка.
